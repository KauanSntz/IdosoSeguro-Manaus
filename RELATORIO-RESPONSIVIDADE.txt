6. A LISTA DE BUGS (por gravidade)
--------------------------------------------------------------------------------

B-R1  *** CRÍTICO ***  Escala de fonte aplicada duas vezes
  Onde:   variables.css:57-70, 118, 252-255
  Como:   html { font-size: calc(18px * --font-scale) }  -> 1rem já escala
          e os tokens fazem calc(1rem * --font-scale)   -> escala de novo
  Efeito: fator real = escala²  (xlarge 1.5 -> 2.25x)
  Medido (1440px):
          escala   1rem    body     botão    parágrafo  fator
          small    15,75   13,78    15,50    17,23      0,77x
          normal   18,00   18,00    20,25    22,50      1,00x
          large    22,50   28,13    31,64    35,16      1,56x
          xlarge   27,00   40,50    45,56    50,63      2,25x
  Corrigir: escolher UMA base. Recomendado: html { font-size: 18px } FIXO
          (ou 100% + 18px no body) e deixar só os tokens multiplicarem por
          --font-scale. Assim a escala é linear (1 / 1.25 / 1.5) e o layout
          não explode. Se preferir escalar o rem, então os tokens NÃO podem
          multiplicar de novo.

B-R2  *** CRÍTICO ***  Tokens inexistentes invalidam declarações
  Onde:   responsive.css:343  padding: var(--space-12) var(--space-16)
          components.css:149  background: var(--color-info-light)
          components.css:1676 font-weight: var(--font-weight-black)
  Efeito: a declaração inteira é descartada. No main (>=1400px) o padding
          vira 0 (medido 0px). No hover do botão de voz, o fundo desaparece.
          No título da tela final, o negrito some.
  Corrigir: criar --space-16 (64px), --color-info-light (#F0F7FC) e
          --font-weight-black (800) OU trocar por tokens existentes.
          Depois rodar a varredura da seção 11 para garantir zero órfãos.

B-R3  *** CRÍTICO ***  Menu do desktop renderizado no fim do conteúdo
  Onde:   public/index.html (ordem: header, main, nav) + responsive.css:116
  Efeito: em >=900px a nav vira `position: static` e, por ser o 3º filho,
          aparece abaixo de todo o conteúdo (medido: top 2876 em xlarge).
          O AGENTS.md afirma que existe "top nav no desktop" — não existe.
  Corrigir: mover o <nav> para DENTRO do header no DOM (ou usar
          `order:-1` no .app-container + `position: sticky`), e tratar a
          nav como parte do header acima de 900px. Nunca deixar a navegação
          principal depender de rolagem.

B-R4  *** CRÍTICO ***  Conteúdo escondido atrás do menu fixo
  Onde:   variables.css:387-401 (fixed) e ausência de compensação
  Efeito: no mobile os últimos 72–80px de cada tela ficam cobertos.
  Corrigir: `body { padding-bottom: calc(var(--nav-height) + env(safe-area-
          inset-bottom) + var(--space-2)) }` somente abaixo de 900px
          (media query), e usar `100dvh` em vez de `100vh`.

B-R5  *** CRÍTICO ***  Não existe camada base (reset não carregado)
  Onde:   public/index.html:14-17 (só 4 arquivos) + public/css/reset.css
          (135 linhas) + public/css/style.css (78 linhas, @import)
  Efeito: sem regras para h1..h6, p, ul, img, a, button; cada página
          reinventa. Medido: `a` sem sublinhado; nenhum h1..h6 genérico.
  Corrigir: decidir UMA camada base (reset.css) e carregá-la ANTES dos
          tokens; apagar style.css (ou transformá-lo no único ponto de
          entrada e atualizar index.html + service-worker).
          Se a opção for "um arquivo só", atualizar o SW (bump de versão)
          senão o usuário fica com CSS antigo em cache.

B-R6  *** ALTO ***  Sem escala tipográfica única (títulos imprevisíveis)
  Onde:   variables.css:491-512 (.title-primary/.title-secondary/.subtitle-main)
          components.css:1258 (.welcome-page .title-primary -> 2xl)
          components.css:928-937 (.page-header-title -> xl)
          components.css:1730 (>=900px: .page-header-title -> 2xl)
          responsive.css:176-177 (>=900px: .title-primary -> 4xl e 4xl*1.2)
  Efeito: mesmo papel (título da tela) com tamanhos diferentes:
          medido em 1440 xlarge -> Welcome 109,35px | outras telas 60,75px
          medido em 1440 normal -> Welcome 27px    | outras telas 27px
          h2: 27px em #aprender/#acessibilidade/#ajuda e 20,25px em #quiz.
  Corrigir: uma única escala (h1 = 2rem, h2 = 1.5rem, h3 = 1.25rem, com
          clamp() para telas grandes), remover TODOS os overrides de título
          por página e o bloco responsive.css:175-178.

B-R7  *** ALTO ***  Padding em três camadas
  Onde:   variables.css:374 (.main-content padding 16/24/40/48)
          components.css:1247+ (11 classes de página, cada uma com
          `padding: var(--space-4)`) + components.css:181 (.card 20px)
  Efeito: no celular 360px: 16 (main) + 16 (página) + 20 (card) = 52px por
          lado -> coluna útil de ~256px para texto de 18px (~26 caracteres
          por linha). É o principal motivo do texto "espremido".
  Corrigir: padding horizontal só no `.main-content` (ou só num wrapper);

B-R8  *** ALTO ***  Anatomia do botão
  Onde:   components.css:6-28 (.btn)
  Problemas:
    - `text-transform: uppercase` + `letter-spacing`: rótulos longos
      ("Ativar leitor de tela", "Escolher outro tipo") ocupam ~15% mais
      largura, viram 3–4 linhas e destroem a leitura de quem tem baixa visão
      (não há ganho de acessibilidade — o leitor de tela lê o texto original).
    - `padding: 0 var(--btn-padding-x)` (ZERO vertical): quando o texto
      quebra, ele encosta na borda superior/inferior.
    - `overflow-wrap: anywhere`: quebra no meio da palavra
      ("Acessibilida / de"), muito ruim para leitores com pouca fluência.
    - `min-height` em px não acompanha 3–4 linhas.
  Medido (simulação de coluna de 360px + xlarge): botão da Welcome com
          221px de altura / 4 linhas; botão da Home 130px / 3 linhas.
  Corrigir: remover uppercase; `padding: var(--space-3) var(--space-5)`;
          `overflow-wrap: break-word`; `min-height` + `align-content:center`;
          breakpoint para empilhar botões.

B-R9  *** ALTO ***  `.btn-back` não encolhe
  Onde:   components.css:938  `flex: 0 0 auto`
  Efeito: dentro de `.page-header` (flex, 917) o botão "Voltar/Escolher

          360px + xlarge: `.page-header` com 399px (quiz) e 566px
          (analisar) dentro de uma coluna de 328px -> estouro horizontal.
  Corrigir: `flex: 0 1 auto; min-width: 0;` e permitir quebra do rótulo.

B-R10 *** ALTO ***  `white-space: nowrap` em textos que precisam quebrar
  Onde:   components.css:1083 (.nav-label), 1096 (.btn-voice .btn-label),

  Efeito: "Falar em vez de digitar" e labels do menu nunca quebram ->

  Corrigir: remover nowrap de .btn-voice/.badge; no menu, permitir 2 linhas
          com `line-height:1.1` ou reduzir o número de itens no mobile.

B-R11 *** ALTO ***  Alturas fixas vs texto fluido
  Onde:   variables.css:139-140, 113-116; responsive.css:20-23, 350-362

11.1 Varrer tokens órfãos (Node, salvar como tmp-scan.cjs na raiz):

    const fs = require("fs");
    const files = ["variables","components","accessibility","responsive"]
      .map(f => `public/css/${f}.css`);
    const def = new Set(), used = new Map();
    for (const f of files) {
      const src = fs.readFileSync(f, "utf8");
      for (const m of src.matchAll(/^\s*(--[a-z0-9-]+)\s*:/gim)) def.add(m[1]);
      src.split(/\r?\n/).forEach((l, i) => {
        for (const m of l.matchAll(/var\(\s*(--[a-z0-9-]+)/g)) {
          if (!used.has(m[1])) used.set(m[1], []);
          used.get(m[1]).push(`${f}:${i+1}`);
        }
      });
    }
    for (const [k, w] of used) if (!def.has(k)) console.log("ORFAO", k, w);
